# Capability-first routing matrix — Maestro

| Task | Creative owner | Implementation | Independent validator | Gate |
| --- | --- | --- | --- | --- |
| Trivial text/one-line fix | Maestro | Maestro | basic test | code |
| Backend/data/API/auth | Technical Architect (strong capable model) | Codex Sol or Claude Sonnet based on stack/available capability | other vendor + tests | code/security |
| Functional ordinary UI | Claude Sonnet or a capable UI developer | assigned builder | design check + functional reviewer | UI/code |
| Premium visual identity, landing page, product UI redesign | Design Director, Claude Opus 5.5 high | Opus for key artboards and critical visuals; bounded Sonnet/Codex for noncreative implementation | Design Director visual sign-off + technical reviewer | premium UI |
| Rich interactive web motion/scroll experiences | Design Director + Motion Director, both Claude Opus 5.5 high | Motion Director Opus ONLY for all animation source; other builders may implement unrelated business logic | Motion Director Opus motion QA + separate technical checks | premium UI/motion |
| Video/brand film/motion graphics/animated carousel | Motion Director Claude Opus 5.5 high | Motion Director Claude Opus 5.5 ONLY | Opus preview inspection + technical render metadata | motion |
| Mechanical build/test/render command | Existing owner | Codex Luna or CLI tools | task-specific checks | code/render |

Never route creative work to an inferior tier purely because an account has quota. If Opus 5.5 is unavailable, stop that part and disclose rather than silently downgrade. Verify installed model identifiers in the actual CLI before execution; documented presets are hypotheses until checked. The Maestro is a coordinator, not a substitute designer.

## Staffing by competencies
- First identify what expertise is missing: art direction, UX research, editorial typography, accessibility, design engineering, complex animation, frontend architecture, QA, backend, security, performance.
- Choose the smallest complete competent team, not a fixed generic trio. One worker may hold several competencies if explicitly qualified.
- Significant premium UI: Design Director -> prototype/render -> UX/accessibility review -> implementation -> visual QA -> technical QA.
- Complex Motion: Motion Director runs creative AND implementation AND rework on Opus 5.5. Do not recruit non-Opus helpers to write motion, including animation snippets.
- Every specialist gets concrete evidence and acceptance gates. Reviewers must be independent where possible, but the Motion model lock still holds.
- User-approved branding, art direction and storyboard are immutable contracts until the user approves a change.

## Alethe-inspired safeguards
Adopt bounded briefs, isolated writes, explicit capability routing, quota checks, checkable results, independent validation, evidence-rich handoffs and rescue only with new context. Do not introduce Alethe as another parallel orchestrator without explicit authorization. Maestri stays the execution surface.

## Decision record
Record task class, selected model/effort, required skills, reason, quota confidence, rejected alternatives, dependencies, review owner, quality gate and exceptions in MISSION.md.
